# My words: graded reading from your own vocabulary

Date: 2026-10-19
Status: approved design, awaiting spec review

## Goal

The HSK levels (1–6) swap in more Chinese than a beginner has learned. Even
level 1 has about 500 words, far more than a Chinese 1 class covers. "My
words" adds a reading mode that swaps in **only** words from a list you
control. You build the list by importing Anki decks (`.apkg`) and adding or
removing words by hand.

Success means: you import your class deck, choose 我的 in the popup, and a page
shows only your class words in Chinese, chosen the same way the HSK levels are
(the Chinese must also appear in Apple's translation of the sentence).

## Non-goals

- No lesson, status or tag filtering. Every word in an imported deck is
  included.
- No review-history filtering. Neither of the user's decks has any reviews.
- No text, CSV or Quizlet import (the user uses Anki).
- No `.colpkg` (full collection) import.
- No sync of the list to Anki or between browsers.

## User interface

### Toolbar popup

- The level row gets a new first button, **我的** (`data-level="0"`):
  `[我的] 1 2 3 4 5 6 全部`.
- When 我的 is selected:
  - The hint reads "Swap my N words". If the list is empty, it reads "Import
    or add words first".
  - An **Edit my words** link opens the My words page.
- The popup reads the word count from `browser.storage.local` (`myWords`).

### My words page (`extension/mywords/mywords.html`)

This is a new extension page, separate from the lookup-history word list
(`vocab/`). The word list page links to it.

- **Import**
  - An "Import Anki deck (.apkg)…" file button.
  - A choice between **Add to my words** (the default) and **Replace my
    words**.
  - A result line, e.g. "Added 31 new words · 186 already in your list · 2
    skipped: 臺灣, …". Skipped notes are those with no Chinese field.
  - Replace asks for confirmation first: "Replace all N words, including
    words you added by hand?"
- **Add a word**
  - A Chinese input field. When it loses focus, the English is filled in from
    CC-CEDICT: the first entry's definitions, up to the first `/`. Pinyin is
    shown next to it.
  - The English can be edited before you click **Add**.
  - Adding a word that is already in the list updates its English.
- **List**
  - A search box that filters on Chinese, pinyin or English, and the word
    count.
  - One row per word: Chinese · pinyin (from CC-CEDICT, tone-colored like the
    rest of the extension) · English · source (deck name, or "added by you") ·
    ✕ to remove it.
  - Clicking a word's English edits it in place. Enter or leaving the field
    saves it.
  - **Remove all** asks for confirmation first.

## Data

`browser.storage.local` key `myWords`:

```js
[{ zh: '住', en: 'to live', source: 'Chinese 1' }, ...]
```

- `zh` is unique. Words are stored in the order they were added.
- `source` is the deck name (from the `decks` table, or from `col.decks` in
  older files, choosing the deck that holds most of the imported cards).
  Words added by hand get `source: ''`.
- Rough size: 217 words take about 10 KB, well within storage limits.

Writes go through the background script. A new message, `setMyWords
{ words }`, replaces the whole list and is accepted only from extension pages
(add it to `src/background/guard.js` beside `importWords`). It validates every
record with `cleanMyWord`: `zh` must be 1–16 Han characters; `en` and `source`
must be strings and are trimmed to 200 characters; there is a 20,000-word
limit. Reads use `browser.storage.local.get('myWords')` directly, the same way
settings are read.

The pure list operations go in `src/shared/mywords.js`:

- `mergeWords(list, incoming, mode)`, where `mode` is `'add'` or `'replace'`.
  It returns `{ words, added, existing }`.
  - In `'add'` mode, an existing word keeps its English and source.
  - Words you removed come back if their deck is imported again with Add.
    This is expected.
- `addWord(list, { zh, en })`, `removeWord(list, zh)`, `editWord(list, zh,
  en)`.

Settings: `level: 0` means My words. `DEFAULT_SETTINGS.level` stays `7`.

## Reading `.apkg` files

All parsing runs on the My words page (an extension page). There is no
WebAssembly and no change to the security policy (CSP).

### Formats seen

| Source | Data entry | Compression | Field names |
|---|---|---|---|
| Generated by `chinese_study` | `collection.anki2` | none | `col.models` JSON |
| Exported from current Anki | `collection.anki21b` (+ a stub `collection.anki2`) | zstd | `fields` table |
| Older Anki "support older versions" export | `collection.anki21` | none | `col.models` JSON |

Which entry to read: `collection.anki21b`, then `collection.anki21`, then
`collection.anki2`. If the only one present is a stub, fail with a clear error.
A stub is a single note whose fields begin "Please update to the latest Anki
version".

### Modules

- **`src/shared/zip.js`**: `readZip(arrayBuffer) -> Map(name -> () =>
  Promise<Uint8Array>)`. It finds the end-of-central-directory record, reads
  the central directory entries, and handles methods 0 (stored) and 8
  (deflate, through `new DecompressionStream('deflate-raw')`). Zip64 and
  encrypted entries are rejected with an error.
- **zstd**: the `fzstd` npm package (pure JS, MIT, about 8 KB), bundled by
  esbuild into the My words page only. `decompress(Uint8Array)`.
- **`src/shared/sqlite.js`**: a minimal read-only SQLite reader.
  - `openDb(Uint8Array) -> { tables(), rows(tableName) }`.
  - Reads the header (page size, including the value 1 meaning 65536) and
    `sqlite_schema` from page 1. It walks table B-trees (interior page `0x05`,
    leaf page `0x0D`), follows overflow page chains, and decodes record
    serial types (NULL, integers of 1–8 bytes, float, 0, 1, BLOB and TEXT as
    UTF-8).
  - It rejects databases that are not UTF-8, as well as WITHOUT ROWID tables.
    It doesn't use indexes, because full scans of a few hundred rows are
    instant.
- **`src/shared/anki.js`**: `readApkg(arrayBuffer) -> { deck, words: [{ zh,
  en }], skipped: [string] }`.
  - **Field names**: from the `fields` table (`ntid, ord, name`) when it
    exists, otherwise from `col.models` JSON (`flds[].name` by `ord`).
  - **Chinese field**: the first field whose name matches
    `/^(hanzi|simplified|chinese|word|front|expression)$/i`, as long as its
    value contains a Han character. Otherwise, the first field whose value is
    mostly Han characters.
  - **English field**: the first field whose name matches
    `/^(meaning|english|definition|translation|back|gloss)$/i`. Otherwise
    it's empty, and English for swapping comes from HSK data alone.
  - **Cleaning field values**: strip HTML tags, decode entities (`&#x27;`,
    `&amp;`, `&nbsp;`, …), remove `[sound:…]` and trim. From the Chinese, keep
    the first run of Han characters (`/\p{Script=Han}+/u`).
  - Notes without Han characters go into `skipped` (by their first field,
    shortened to 20 characters). Duplicate `zh` values within a deck are
    merged, keeping the first.

## Swapping

`src/background/graded.js` gains a second map:

- When `level === 0`, it builds (and caches) a word map from `myWords` with
  the same structure as the HSK map: lowercase English → `[{ zh, level: 0 }]`.
  It has two sources:
  1. Each word's `en`, split on `;` `,` `/`, then cleaned with the same
     `cleanGloss` rules as `scripts/build-hsk.mjs`. Move `cleanGloss` and the
     `STOP` set to `src/shared/gloss.js` so both can use them. Keep only
     glosses matching `^[a-z]+(?:[ -][a-z]+){0,2}$` that aren't in `STOP`.
  2. Every English key in the HSK map whose candidates include one of your
     words.
- The cached map is cleared on `browser.storage.onChanged` for `myWords`.
- `diglotItem(item, translation, map, 0)` then works unchanged, since every
  candidate has `level: 0 <= 0`. The translation check still applies.
- If the list is empty, nothing is swapped (the page stays English).
- Translations are cached by English text, not by level, so switching levels
  needs no new translation.
- Lookup history, hover and pinyin behave exactly as at the HSK levels.

The content script and translator already pass `level` through without
checking it. Make sure every place that treats `level` as 1–7 also accepts 0:
`translate.js` `setLevel`, the popup `levelHint`, and `LEVELS` in `diglot.js`.

## Build

- `scripts/build.mjs` adds the entry `src/mywords/mywords.js` ->
  `extension/dist/mywords.js`, and copies `extension/mywords/` into the
  Chrome build like the other pages.
- `npm install fzstd` (dependency). `zstd` from npm, or `node:zlib`'s
  `zstdCompressSync` if the Node version has it, is used only by the tests
  (devDependency, or nothing at all).

## Testing

Unit tests (`node --test 'test/unit/*.test.js'`):

- **`zip.test.js`**: reading a stored and a deflated entry (fixture made with
  `node:zlib` `deflateRawSync` plus hand-written headers), plus the errors for
  a missing EOCD and for zip64.
- **`sqlite.test.js`**: a database built with `node:sqlite`, then read back:
  - integer, float, text, NULL and blob values;
  - a table spanning several pages (an interior page);
  - a row longer than a page (overflow);
  - page size 65536.
- **`anki.test.js`**: synthetic `.apkg` files built in the test:
  - a legacy one (`anki2` + `col.models`);
  - a modern one (`anki21b` zstd + `fields` table + stub `anki2`);
  - a stub-only one, which should produce an error;
  - HTML, entities and sound tags stripped; field fallback; skipped notes.
- **`mywords.test.js`**:
  - `mergeWords` with add and replace (counts, keeping edits);
  - `addWord`, `removeWord`, `editWord`;
  - `cleanMyWord` validation;
  - building the word map;
  - `findSwaps` at level 0 swapping only list words, e.g. "I live in a big
    house" with 住 and 大 in the list.

One-off check (not committed): run `readApkg` against
`~/chinese_study/build/chinese1.apkg` and `~/Documents/Chinese 1.apkg`. Both
should give 217 words from the "Chinese 1" deck.

Manual check in Chrome:

1. Import the Anki export.
2. Choose 我的 in the popup.
3. On an English page, check that only your words appear in Chinese and that
   hover works.
4. Add and remove a word, and check that the page follows after a reload.
5. Test Replace and Remove all.
